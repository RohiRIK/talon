# ADR 0001 — Rust Edition 2024

**Status:** Accepted  
**Date:** 2026-05-27

## Context

Rust Edition 2024 became stable in February 2025. It enables native `async fn in trait` syntax, eliminating the need for the `async-trait` proc-macro crate. This is the most impactful edition change for async Rust library design.

## Decision

All crates in the workspace use `edition = "2024"`.

## Consequences

**Positive:**
- `async fn` in trait definitions works without any helper crate
- `async-trait` is explicitly banned in `deny.toml` — any accidental dependency on it will fail `cargo deny check`
- Simpler trait definitions, no `Box<dyn Future>` boilerplate for the common case

**Negative / Watch:**
- Some ecosystem crates haven't updated to edition 2024 — they still compile as dependencies, but transitively pulling in `async-trait` via a dep is possible. `cargo deny` catches this.
- Object safety: `async fn in trait` methods are NOT object-safe by default. If `dyn LlmProvider` is required, the trait method must return `Pin<Box<dyn Future + Send>>`, or use concrete enum dispatch. This is documented in ADR 0003.

## Alternatives Considered

- **Edition 2021:** Would require `async-trait` for the LlmProvider and Tool traits. Rejected — `async-trait` adds a proc-macro dependency and hides the `Pin<Box<dyn Future>>` complexity instead of surfacing it.
