## Terminal Image Protocols

Modern terminals support inline images. Talon should detect and use the best available protocol.

| Protocol | Terminals | Resolution | How |
|---|---|---|---|
| **Kitty** | Kitty, WezTerm, Ghostty | Full resolution | Base64 PNG via escape sequences |
| **iTerm2** | iTerm2, WezTerm, Mintty | Full resolution | Base64 via OSC 1337 |
| **Sixel** | XTerm, mlterm, foot, WezTerm | Full resolution | Sixel-encoded raster data |
| **Halfblocks** | Any terminal | Low (~half char height) | Unicode ▀▄ blocks with colors |

### Rust Crate: `ratatui-image`

```rust
use ratatui_image::{StatefulImage, protocol::StatefulProtocol};

// Auto-detect best protocol for current terminal
let protocol = ratatui_image::picker::Picker::from_termios()?;
let image = StatefulImage::new(protocol.new_resize_protocol(dynamic_image));
frame.render_stateful_widget(image, area, &mut image_state);
```

**Talon use cases:**
- Rendering charts/diagrams generated by tools
- Showing screenshots from browser automation
- Image analysis results displayed alongside text

## Terminal Markdown Rendering

### Strategy: comrak (parse) → syntect (highlight) → custom ratatui widgets

```
Markdown text → comrak AST → Talon renderer → ratatui Spans/Lines
                                  ↓
                           syntect for code blocks
```

### Key Crates

| Crate | Role |
|---|---|
| `comrak` | GFM-compatible markdown parser, produces AST |
| `syntect` | Syntax highlighting using Sublime Text grammars |
| `termimad` | Alternative: complete markdown-to-terminal renderer |

### Streaming Markdown Challenge

LLM output arrives token-by-token. The markdown might be incomplete mid-stream:

```
"Here's the code:\n```rust\nfn main() {"  ← incomplete code block
```

**Approach:**
1. Buffer incoming tokens
2. Parse with comrak on each render frame
3. Detect unclosed blocks (code fence, list, etc.)
4. Render complete elements normally, show incomplete elements with visual indicator
5. Re-parse when more tokens arrive

### Terminal Markdown vs HTML Mapping

| Markdown | Terminal Rendering |
|---|---|
| `# Heading` | Bold + color + top/bottom padding |
| `**bold**` | Bold attribute |
| `*italic*` | Italic attribute (terminal support varies) |
| `` `code` `` | Colored background span |
| ```` ```lang ```` | syntect-highlighted block with border |
| `> quote` | Left border bar + dimmed text |
| `- list` | Indented with bullet character |
| `[link](url)` | Underlined + color (clickable via OSC 8) |
| `| table |` | Box-drawing characters |
| `![image](url)` | Inline image via protocol detection |

Modern terminals support hyperlinks:

Talon should render markdown links as clickable terminal hyperlinks where supported.

## Accessibility

### Requirements

1. **`--accessible` / `--no-tui` flag** — disables full-screen TUI, uses line-by-line output
2. **`NO_COLOR` environment variable** — strip all color output
3. **`$TERM=dumb`** — auto-detect and fall back to plain mode
4. **Screen reader friendly** — structured output in non-TUI mode
5. **High contrast theme** — ship a WCAG-compliant theme

### Implementation

```rust
fn detect_capabilities() -> RenderMode {
    if std::env::var("NO_COLOR").is_ok() || std::env::var("TERM") == Ok("dumb".into()) {
        RenderMode::Plain
    } else if args.accessible {
        RenderMode::Accessible  // line-by-line, no escape sequences
    } else {
        RenderMode::TUI  // full ratatui
    }
}
```

## Multiplexer Awareness

Detect if running inside tmux/zellij and adapt:

```rust
fn detect_multiplexer() -> Option<Multiplexer> {
    if std::env::var("TMUX").is_ok() { Some(Multiplexer::Tmux) }
    else if std::env::var("ZELLIJ").is_ok() { Some(Multiplexer::Zellij) }
    else { None }
}
```

**Multi-pane workflows:**
- Spawn tool execution in adjacent pane
- Show file diffs in side pane

## Diff Rendering

Using `similar` crate for unified diffs with syntax highlighting:

```rust
use similar::{ChangeTag, TextDiff};

let diff = TextDiff::from_lines(old, new);
for change in diff.iter_all_changes() {
    let style = match change.tag() {
        ChangeTag::Delete => Style::default().fg(Color::Red),
        ChangeTag::Insert => Style::default().fg(Color::Green),
        ChangeTag::Equal => Style::default().fg(Color::DarkGray),
    };
    // Render as ratatui Line with style
}
```

Critical for showing proposed file changes before agent applies them.
